# تقرير حالة المحرك الحالي — Rio4140 Engine v1 (فعلي، لا أهداف)

- **تاريخ التقرير:** 5 نوفمبر 2026، بعد إعادة بناء واختبار
  فعلية في نفس اليوم (الأوامر والنتائج أدناه من تشغيل حقيقي،
  وليست أرقاما من وثيقة سابقة).
- **الحالة العامة:** محرك مستقل يعمل، وليس لغة كاملة بعد.
  كل ما يذكر هنا كـ "منفذ" له كود واختبار. كل ما يذكر
  كـ "مخطط" ليس منفذا، ولا يدعى أنه منفذ.

## 1. ما تم تنفيذه فعلا

- **اللغة:** Rust فقط، std فقط، لا مكتبات خارجية.
- **المحلل:** Lexer + Parser + AST، مع سطر وعمود لكل عقدة.
- **التنفيذ:** Tree-Walking Interpreter، ملف تنفيذي واحد
  اسمه `rio`، لا يحول البرامج إلى Python، ولا إلى لغة آلة.
- **الكود:** `src/lexer.rs` (371 سطرا)، `src/parser.rs`
  (687 سطرا)، `src/ast.rs` (102)، `src/value.rs` (91)،
  `src/interpreter.rs` (1077)، `src/main.rs` (90)،
  `src/error.rs` (69). المجموع مع الاختبارات وCargo:
  2645 سطرا (بما فيها اختبارات التكامل).
- **الملفات في المحرك:** 20 ملفا (Cargo.toml، Cargo.lock،
  DESIGN.md، README.md، 8 أمثلة ‎.rio، 7 ملفات مصدر
  Rust، ملف اختبار تكامل واحد). صفر ملفات Python
  داخل مجلد المحرك.
- **الأوامر المنفذة:**
  - متغيرات، طباعة `اطبع` (بأقواس ومن غير أقواس)،
    شروط `إذا / وإلا إذا / وإلا`، حلقات `بينما`،
    `لكل ... في ...`، `كرر N مرات`، `كرر طالما`،
    دوال `دالة / ارجع`، قوائم، قواميس، فهرسة،
    محاولة `حاول / ماعدا / أخيرا`، تعيين فهرسة،
    تعليقات `#`، نصوص، أرقام عربية وغربية،
    ترقيم عربي `، ؛`.
  - الكلمات المحجوزة في Lexer: 27 كلمة. منها
    23 منفذة في Parser، و2 مرفوضة صراحة
    برسالة واضحة (فئة، استورد)، و2 محجوزة
    غير مستخدمة في Parser بعد (من، باسم)،
    فاستخدامهما حاليا يعطي خطأ نحويا، لا سلوكا.
  - الدوال المدمجة المنفذة: 12 دالة: طول، مدى،
    مجموع، أدنى، أقصى، مطلق، عدد، نص، نوع،
    اقرأ_ملف، اكتب_ملف، ادخل. بالإضافة إلى
    `اطبع` كجملة، لا كدالة.
  - النطاق: دالة تفتح نطاقا جديدا، ومتغير داخل
    الدالة غير متاح خارجها (مختبر). الحلقة
    والشرط لا يفتحان نطاقا، ومتغير الحلقة
    يبقى بعدها (مختبر).
  - الأنواع: ديناميكية، مع فحص وقت التشغيل،
    وشروط يجب أن تكون منطقية، وتحويل صريح
    فقط عبر `عدد()` و`نص()`، و`نوع()` يعيد
    اسم النوع بالعربي.
  - الأخطاء: عربية، فيها النوع والسطر والعمود:
    لغوي، نحوي، نوع، وقت تشغيل، إدخال/إخراج.
    مثال فعلي: `خطأ نوع: لا يمكن جمع نص وعدد`.

## 2. ما لم ينفذ بعد (صراحة، لا يدعى)

- لا فئات، ولا وراثة، ولا واجهات في المحرك.
  `فئة` ترفض برسالة: "الفئات غير مدعومة في
  المحرك v1".
- لا استيراد/تصدير، ولا وحدات، ولا حزم.
  `استورد` ترفض برسالة واضحة.
- لا وصول بالنقطة (مثل `قاموس.values()`).
- لا Bytecode VM، ولا مترجم أصلي AOT، ولا JIT.
- لا GC: إدارة الذاكرة الحالية هي ملكية Rust
  + نسخ القيم، وليست جامعا تتبعيا. تصميم GC
  في وثيقة v1.1 هو لمرحلة VM، لا وصف للحالي.
- لا مصحح، ولا مدير حزم، ولا محرر رسمي،
  ولا FFI، ولا مكتبة قياسية بوحدات.
- لا دعم Windows أو Android أو macOS أو iOS
  مبني بعد. النسخة المبنية هنا Linux فقط.
- لا اختبارات Fuzzing أو ضغط أو تسرب ذاكرة
  أو أمنية بعد. الاختبارات الحالية هي وحدة
  وتكامل وأمثلة فقط (انظر القسم 4).
- لا أرقام أداء مقاسة بعد. لا يوجد Benchmark
  رسمي منفذ، ولا مقارنة سرعة معلنة.

## 3. أوامر إعادة البناء والاختبار (منسوخة من تشغيل فعلي)

المتطلب الوحيد للبناء: أدوات Rust (cargo/rustc).
التشغيل لا يحتاج Python، ولا أي وقت تشغيل آخر.

```bash
# من مجلد المحرك:
cd ~/workspace/rio4140-language/engine

# البناء (تطوير):
cargo build

# البناء النهائي (Release):
cargo build --release
# الناتج: ./target/release/rio  (725K، في التشغيل الأخير)

# الاختبارات الرسمية:
cargo test

# تشغيل برنامج:
./target/release/rio examples/08-full-program.rio

# عرض شجرة AST ثم التشغيل:
./target/release/rio examples/01-hello.rio --ast

# المساعدة والإصدار:
./target/release/rio --help
./target/release/rio --version
# الناتج: Rio4140 engine 1.0.0 (Rust, Tree-Walking Interpreter, no Python)
```

إصدار الأدوات في التشغيل الأخير:
`rustc 1.99.1`، `cargo 1.99.1` (عبر rustup، ملف شخصي minimal).

## ملحق v1.2 — تصحيح توثيق الحدود (5 نوفمبر 2026، دون تغيير الكود)

هذا الملحق يصحح فجوات توثيقية في التقرير
الأصلي أعلاه، دون تعديل أي نتيجة سابقة،
ودون تغيير أي كود. التقرير الأصلي يبقى
كما هو، والملحق يضيف ما كان ناقصا.

### أ. حد المليون تكرار (كان غير موثق في التقرير الأصلي)

صاحب اللغة محق: الحد كان مذكورا في وثيقة
v1.1، لكنه لم يكن مذكورا في هذا التقرير.
البحث في التقرير الأصلي أثبت عدم وجود
أي ذكر لـ "مليون" أو "1,000,000".

**الحد الدقيق، من الكود الفعلي:**
في `src/interpreter.rs`، السطر 25:

```
const MAX_LOOP_ITERATIONS: usize = 1_000_000;
```

يستخدم في ثلاثة أماكن فقط:

- `كرر N مرات`: إذا كان N > 1,000,000،
  يرفض قبل البدء، بخطأ: "عدد مرات التكرار
  كبير جدا".
- `بينما` / `كرر طالما`: عدد تكرارات
  الحلقة نفسها، وإذا تجاوز 1,000,000،
  يخطئ: "تم تجاوز حد التكرار، هل الحلقة
  لا تنتهي؟".
- `مدى`: طول القائمة الناتجة، وإذا تجاوز
  1,000,000، يخطئ: "نطاق مدى كبير جدا".

**ما لا يحسبه الحد:** عدد أسطر البرنامج،
ولا حجم القوائم العامة، ولا التكرارات
التراكمية عبر حلقات متتالية، ولا تكرارات
الحلقات المتداخلة مجتمعة. كل حلقة لها
حدها الخاص.

**طبيعة الحد:** حد أمان تشغيلي في v1،
وليس قاعدة لغوية. في المرحلة 1، يصبح
قابلا للتهيئة للبرنامج الرئيسي، ويبقى
1,000,000 افتراضيا للحزم، ولا تستطيع
حزمة رفعه بنفسها. انظر وثيقة v1.2، القسم 7.

### ب. المقارنات المتسلسلة: فجوة موثقة

المحرك الحالي لا يدعم المقارنات المتسلسلة
بمعنى Python. التشغيل الفعلي لبرنامج:

```
س = ٥
إذا ١ < س < ١٠:
    اطبع "سلسلة صح"
```

يعطي، فعلا:

```
خطأ نوع: المقارنة تتطلب عددين أو نصين،
وليس منطقي و عدد (السطر 2، العمود 11)
```

لأن Parser الحالي يساري الترابط: `(١ < س) < ١٠`.
الدلالة الصحيحة (سلسلة مع تقييم مرة واحدة
واختصار) مواصفة في وثيقة v1.2، القسم 1.3،
وتنفيذها مطلوب في المرحلة 1، وليست
منفذة في v1.

### ج. عمق الاستدعاء: فجوة خطيرة موثقة

**لا حد لعمق الاستدعاء في المحرك الحالي.**
لا يوجد أي فحص لعمق المكدس في الكود.
التشغيل الفعلي لبرنامج استدعاء ذاتي لا نهائي:

```
دالة عميقة(ن):
    ارجع عميقة(ن + ١)
اطبع عميقة(٠)
```

يعطي، فعلا:

```
thread 'main' has overflowed its stack
fatal runtime error: stack overflow, aborting
```

هذا انهيار، لا خطأ Rio، ولا رسالة عربية.
التصحيح المطلوب في المرحلة 1: حد عمق
استدعاء صريح (مقترح أولي: 10,000 إطار)،
مع خطأ Rio عربي، واختبار ضغط يثبت عمله.
انظر وثيقة v1.2، القسم 7.4.

### د. ما لم يتغير بهذا الملحق

- لا كود تغير، ولا اختبار تغير، ولا نتيجة
  سابقة تغيرت.
- الملحق توثيق فقط، لتصحيح ما كان ناقصا،
  ولمنع ادعاء أي حد أو ميزة دون توثيق.
- أي حد أو ميزة يذكر في وثائق لاحقة دون
  وجوده في الكود والاختبار يعتبر خطأ
  توثيقيا، ويصحح بنفس الطريقة: ملحق
  مؤرخ، لا تعديل صامت للتاريخ.

## ملحق v1.3 — إصلاح P0-1: حد عمق الاستدعاء (5 نوفمبر 2026، كود + اختبار)

هذا الملحق يوثق تغييرا كوديا واحدا،
طلبه صاحب اللغة صراحة في مراجعته
النهائية لـ v1.2، ولا يعدل أي نتيجة
سابقة أخرى.

### ما تم تنفيذه

- في `src/interpreter.rs`: ثابت
  `MAX_CALL_DEPTH = 200`، وحقل
  `call_depth` في المفسر، وفحص قبل
  كل استدعاء دالة مستخدم: إذا وصل
  العمق إلى 200، يعيد خطأ وقت تشغيل
  عربي: "تجاوز حد عمق الاستدعاء (200).
  أوقف الاستدعاء الذاتي أو قلل عمقه"،
  مع السطر والعمود. العمق يخفض في
  كل مسار خروج، بما فيه الأخطاء.
- لماذا 200؟ قياس تجريبي 5 نوفمبر 2026:
  بناء Debug ينهار عند عمق ~220–250
  (إطارات غير محسنة، مكدس 8 MB)،
  وبناء Release يتحمل 1000+. حد 1000
  أولي كان ما زال ينهار تحت `cargo test`
  (Debug). 200 آمن في كلا البنائين،
  بهامش. في Phase 1B (VM) سيكون هناك
  مكدس استدعاء صريح، وسيرتفع الحد.
- لا تغيير في دلالة اللغة، ولا في
  النطاقات، ولا في الأنواع. البرامج
  بعمق أقل من 200 ما زالت تعمل.

### الاختبارات الجديدة، والنتائج الفعلية

```
cargo test (5 نوفمبر 2026)
  9 unit tests passed (كما قبل)
  8 integration tests passed (كانت 6، صارت 8)
  0 failed
```

- `recursion_depth_limit_returns_arabic_error_not_crash`:
  استدعاء ذاتي لا نهائي، يفشل بخروج
  غير 0، وبخطأ يحتوي "عمق الاستدعاء"
  و"السطر"، ولا يحتوي "stack overflow".
- `shallow_recursion_still_works_and_depth_is_released`:
  استدعاء بعمق 100 ثم 10، يعملان،
  ويطبعان 100 و10، ليثبت أن العمق
  يعود إلى صفر بعد كل استدعاء.

تشغيل يدوي، Debug وRelease، لبرنامج
استدعاء لا نهائي: كلاهما يعطي الآن
خطأ وقت تشغيل عربيا، وخروج 1،
لا انهيارا. الفجوة الموثقة في ملحق
v1.2 (Stack Overflow) **مغلقة الآن**
بالنسبة لدوال المستخدم في مفسر الشجرة.

### ما لم يتغير بهذا الملحق

- كل نتائج التقرير الأصلي وملحق v1.2
  تبقى كما هي، ما عدا هذه الفجوة
  المغلقة.
- المقارنات المتسلسلة ما زالت غير
  منفذة في v1 (فجوة ملحق v1.2)،
  والفئات والوحدات والوصول بالنقطة
  ما زالت غير منفذة، وGC وVM والمصحح
  والحزم ما زالت غير منفذة. وثيقة
  v1.3 هي المواصفة لها، لا تنفيذها.
- هذا الملحق، ووثيقة v1.3، محليان،
  ولم يرفعا إلى المستودع العام بعد.

## ملحق Phase 1A — الخطوة 1: المحلل الدلالي (5 نوفمبر 2026، بعد موافقة صاحب اللغة على البدء)

بناء على موافقة صاحب اللغة «ابدأ الان انا

## محضر اجتماع 2 — نطاق RTL (2026-11-05، محلي فقط)

- **السؤال، بأمر صاحب اللغة «تمام ابدأ تصويت»:**
  هل الكود يكون من اليمين للشمال، وبالعربي،
  ورسائل الخطأ بالعربي، وكل شيء بالعربي؟
  الاجتماع يصوت على النطاق، لا على معاد زمني
  مخترع. رسائل الخطأ والكلمات والأنواع عربية
  أصلا، فالسؤال الحقيقي هو RTL.
- **الأعضاء نفس أدوار الاجتماع 1، بنفس المعايير:**
  مصمم اللغة، منفذ المحرك، تجربة المبتدئ،
  التوافق والاستقرار، الجودة والأمان.
  أكثر تصويت يفوز، والتعادل يحسمه مصمم اللغة.
- **الخيارات:**
  - أ: عرض RTL فقط في محرر/ملعب رسمي
    (عرض ثنائي الاتجاه، الترتيب المنطقي للملف
    والصيغة كما هما، بلا تغيير في المحرك).
  - ب: صيغة RTL (عكس ترتيب الرموز، مثل
    `٥ = س` بدل `س = ٥`)، تغيير كاسر.
  - ج: عرض + صيغة RTL معا.
  - د: لا تغيير الآن، يبقى LTR، والتركيز على
    قلب المحرك (الوراثة/الواجهات، ثم VM).
- **الأصوات:**
  - مصمم اللغة: أ — عرض RTL يعطي إحساسا
    عربيا كاملا للمبتدئ، من غير كسر الصيغة
    التي يتعلمها في أي لغة أخرى، ومن غير كسر
    كل برنامج موجود.
  - منفذ المحرك: د — عرض RTL شغل محرر،
    لا محرك، ولو بدأ الآن سيسحب وقتا من قلب
    المحرك، والمحرر أصلا مرحلة أدوات لاحقة.
    الصيغة RTL إعادة كتابة للمحلل وكل الاختبارات.
  - تجربة المبتدئ: أ — المبتدئ يقرأ العربية
    من اليمين، فعرض RTL يساعده يقرأ الكود
    كنص عربي، بينما عكس الصيغة يصعب عليه
    التعلم لأنه يعكس اتجاه التعيين والاستدعاء
    الذي يراه في الرياضيات ولغات أخرى.
  - التوافق والاستقرار: د — حتى العرض RTL
    قد يربك عند نسخ الكود لمحرر آخر LTR،
    لأن الملف على القرص يبقى LTR منطقيا،
    والعرض يختلف عن الملف. الأمان الآن هو
    عدم تغيير ما يعمل.
  - الجودة والأمان: أ — عرض RTL لا يمس
    اختبارات المحرك ولا صحته، فهو آمن من
    جهة المحرك، بينما الصيغة RTL خطر اختبار
    كبير وفرصة أخطاء محلل جديدة.
- **النتيجة: أ يفوز 3-2 (د: 2، ب: 0، ج: 0).**
  النطاق المعتمد هو عرض RTL فقط، في محرر/
  ملعب رسمي مستقبلي، بلا تغيير في صيغة
  المحرك ولا في ترتيب الرموز ولا في الملفات.
  صيغة المحرك تبقى LTR، وكل البرامج والأمثلة
  والاختبارات الحالية سارية كما هي.
- **ما لم يقرره هذا الاجتماع:**
  معاد بناء المحرر، ولا أرقام الطباعة (غربية
  كما هي، سؤال مستقل إن طلب)، ولا أسماء
  ملفات الأمثلة. صاحب اللغة يحتفظ بحق النقض
  كمالك، لكن العمل لا يتوقف انتظارا لرأيه وحده.

## محضر اجتماع 10 — إعادة ترتيب الخطة حسب التحليل الخارجي (2026-11-05، محلي فقط)

## محضر اجتماع 11 — قاعدة التعيين مع الـ closures (2026-11-05، محلي فقط)

- **السياق:** أثناء بناء الـ closures ظهر
  قرار تصميمي: التعيين الحالي يعرف
  متغيرا محليا دائما (`س = ٢٠` داخل
  دالة تظلل `س` الخارجية، والخارجية
  تبقى ١٠ — موثق في مثال 05). وبهذه
  القاعدة لا يعمل نمط العداد الكلاسيكي
  (`ع = ع + ١` داخل closure يعرف محليا
  ويرجع 1 كل مرة)، فتصبح الـ closures
  قراءة فقط.
- **السؤال:** ماذا يفعل `س = ...` داخل
  دالة/closure عندما توجد `س` في نطاق
  خارجي؟
- **الخيارات:**
  - أ: تعيين معجمي — يعين لأقرب ربط
    موجود (يمشي السلسلة)، ويعرف محليا
    فقط إذا لم يوجد الاسم في أي مكان.
    العداد يعمل؛ والدوال تستطيع تعديل
    متغيرات خارجية/عامة. تغيير كاسر
    لقاعدة التظليل الموثقة.
  - ب: يبقى التعيين محليا دائما — الـ
    closures قراءة فقط للمتغيرات
    الخارجية؛ والعداد لا يعمل.
  - ج: يبقى التعيين محليا الآن + إعلان
    صريح بأسلوب nonlocal لاحقا؛ والـ
    closures قراءة فقط في هذه الشريحة.
- **الأصوات:**
  - مصمم اللغة: أ — closure بلا حالة
    زينة؛ وJS وLua وRuby تحل التعيين
    عبر السلسلة؛ وv1 هو وقت الإصلاح،
    قبل أن يعتمد أحد على التظليل.
  - منفذ المحرك: أ — قاعدة واحدة في
    كل مكان أبسط في التنفيذ والاستدلال؛
    وب تحتاج قاعدتي تعيين (استدعاء
    closure مقابل استدعاء عادي).
  - تجربة المبتدئ: أ — المبتدئ يتوقع
    أن `س = س + ١` داخل دالة يغير `س`؛
    والتظليل الحالي هو المفاجأة الأولى
    (كما في بايثون).
  - التوافق والاستقرار: ب — قاعدة
    التظليل موثقة (مثال 05 والمحلل)
    وبرامج قائمة قد تعتمد عليها؛ وتغيير
    سلوك صامت خطر استقرار.
  - الجودة والأمان: ج — أ يسهل تعديل
    عام بالخطأ (خطأ كتابة داخل دالة
    يغير عاما بصمت)؛ وب تحافظ على
    الافتراضي الآمن؛ والإعلان الصريح
    هو تصميم بايثون المثبت.
- **النتيجة: أ 3 — ب 1 — ج 1. يعتمد
  التعيين المعجمي.**
- **الأثر:** مثال 05 ما زال صحيحا
  (متغير يعرف لأول مرة داخل دالة لا
  يخرج منها)؛ وما يتغير فقط هو التعيين
  لاسم موجود خارجيا. ومتغير الحلقة
  يبقى يعرف في النطاق الحالي
  (define_local)، لا يعدل عاما بنفس
  الاسم. والمحلل الدلالي يطابق القاعدة
  الجديدة (لا يعرف محليا جديدا عند
  التعيين لاسم خارجي، ويفحص النوع
  المعلن في الربط الموجود).

## الاجتماع 13 — صياغة الـ lambdas (2026-11-05)

- **السياق:** بأمره «ابدأ» (بناء الـ
  lambdas، البند التالي في الخطوة 1).
  وثيقة التصميم اقترحت المصطلح
  `دالة_مجهولة` (أو لامدا، والعربي أولى)
  بلا صياغة كاملة، والـ grammar في v1.2
  تستبعد الـ lambdas صراحة. فالصياغة
  قرار تصميم يحتاج اجتماعا قبل البناء.
- **السؤال:** صياغة الـ lambda: أ
  `دالة_مجهولة(س): س + 1` (تعبير واحد،
  إرجاع ضمني) / ب `لامدا(س): س + 1`
  (نفس الشكل بمصطلح مستعار قصير) / ج
  `دالة(س):` + كتلة (إعادة استخدام
  كلمة دالة، جسم متعدد الجمل) / د
  `دالة_مجهولة(س):` + كتلة.
  الأصوات: مصمم اللغة أ (الوثيقة
  اقترحت المصطلح؛ والـ lambda للتمرير
  لدوال عليا فجسم التعبير الواحد
  يكفي)، منفذ المحرك أ (أصغر تنفيذ:
  تعبير واحد يعيد استخدام آلة الـ
  closures مباشرة؛ والكتلة داخل تعبير
  تعقد المحلل ومنطق استمرار REPL)،
  مبتدئ UX أ (`دالة_مجهولة` تفهم من
  أول نظرة؛ ولامدا كلمة غريبة على
  المبتدئ)، توافق/استقرار أ (الشكل
  التعبيري أقل غموضا ولا يضغط قواعد
  إغلاق الكتل في المعجم)، جودة/أمان أ
  (التعبير الواحد يفرض بالبناء أن تبقى
  الـ lambda صغيرة). **أ يفوز 5-0.**
  الشرط (جودة/أمان): تعبير واحد فقط
  في v1، بلا جمل داخلية؛ والشكل الكتلي
  قد يضاف لاحقا إن احتاجه عمل حقيقي.
- **الأثر:** الـ lambda قيمة دالة
  كاملة (تلتقط معجميا كالـ closures،
  تمرر كوسيط، ترجع من دالة). والحد
  المترتب على التعبير الواحد: الـ lambda
  لا تستطيع الإسناد (الإسناد جملة لا
  تعبير)، فتقرأ المتغيرات الملتقطة ولا
  تعدلها؛ ومن يحتاج تعديلا يستخدم دالة
  مسماة أو يستدعي دالة مسماة تعدل.
  ومعاملات الـ lambda تقبل نفس أنواع
  الدوال المسماة (اتساقا، بلا تصويت
  منفصل).

  (كتابة RTL في الملعب) مفتوحة أصلا
  (اجتماع 2، الخيار أ، والتحقق الحي
  19:32).
- **الأعضاء نفس أدوار الاجتماع 1، بنفس
  المعايير:** مصمم اللغة، منفذ المحرك،
  تجربة المبتدئ، التوافق والاستقرار،
  الجودة والأمان. أكثر تصويت يفوز،
  والتعادل يحسمه مصمم اللغة.

### س1: ما نطاق «التعريب الحقيقي»؟

- أ: الاتجاه فقط — عرض RTL على كل سطح
  (الملعب منجز؛ وأمثلة التوثيق، وعرض
  REPL، وVS Code)، والصيغة والترتيب
  المنطقي كما هما بلا تغيير.
- ب: الاتجاه + كلمات عربية للعلامات —
  عرض RTL في كل مكان، وكلمات عربية
  للعلامات (المقارنات كلمات)،
  والرموز تبقى صالحة (إضافة لا استبدال).
- ج: الاتجاه + عكس الصيغة — عرض RTL
  وصيغة RTL (عكس ترتيب الرموز)، تغيير
  كاسر لكل البرامج الموجودة.
- د: كل شيء — عرض RTL + علامات عربية
  + عكس الصيغة + أرقام عربية فقط +
  أسماء أوامر وامتداد عربية.

- **مصمم اللغة: ب** — التعريب الحقيقي
  يعني أن الكود يُقرأ كعربي، لا أن
  يعرض كعربي فقط؛ وكلمات العلامات
  تلغي التباس العلامات المعكوسة
  وتعمّق الهوية، من غير عكس ترتيب
  الرموز.
- **منفذ المحرك: أ** — بلا تغيير في
  المحرك؛ وباء نحو جديد في المحلل
  (تكلفة متوسطة ومسارات جديدة)،
  وجيم ودال إعادة كتابة للمحلل وكل
  الاختبارات.
- **تجربة المبتدئ: ب** — العلامتان
  المعكوستان بصريا فخ قراءة حقيقي
  للمبتدئ؛ وكلمات مثل «أكبر من»
  و«أصغر من» و«يساوي» تُقرأ بلا
  التباس من اليمين.
- **التوافق والاستقرار: أ** — صفر
  كسر؛ وباء كإضافة تضاعف سطح الصيغة
  ومصفوفة الاختبارات، وجيم ودال
  تكسر كل برنامج موجود.
- **الجودة والأمان: أ** — عرض RTL
  مثبَت وقابل للاختبار؛ وكل مسار
  صيغة جديد خطر جديد؛ وانعكاس
  العلامات عيب عرض لا عيب صحة
  (المحرك صحيح).

- **النتيجة: أ يفوز 3-2** (أ: المحرك،
  التوافق، الجودة؛ ب: المصمم،
  المبتدئ). فالطريق هو: عرض RTL
  على كل سطح، والصيغة كما هي.
  وباء (كلمات عربية للعلامات
  كإضافة) تبقى مفتوحة كقرار لاحق
  مستقل — لم تُقتل، ولم تدخل الطريق
  الآن.

### س2: ما أول خطوة على الطريق؟

- أ: اختبار برنامج حقيقي RTL — مثال
  البرنامج الكامل (08) في الملعب،
  والحكم على القراءة (وهو الحكم)
  قبل بناء المزيد.
- ب: أمثلة التوثيق RTL — كتل كود
  التوثيق RTL.
- ج: قرار العلامات أولا — حسم
  الكلمات مقابل الرموز لأنه يؤثر
  في اللغة كلها.
- د: VS Code RTL — إعدادات RTL في
  الإضافة.

- **مصمم اللغة: أ** — الحكم على
  القراءة في برنامج حقيقي أولا؛
  وكل ما بعده يتوقف على هذا الحكم.
- **منفذ المحرك: أ** — الاختبار بلا
  كود (لا تكلفة)، ونتيجته تقرر إن
  كانت تغييرات أعمق لازمة.
- **تجربة المبتدئ: أ** — المبتدئ
  (وهو) هو الحكم؛ والبرنامج
  الحقيقي هو الاختبار الصادق
  الوحيد.
- **التوافق والاستقرار: أ** —
  اختبار محض لا يكسر شيئا.
- **الجودة والأمان: أ** — اختبار
  القراءة هو البوابة القابلة
  للقياس؛ وبناء أسطح عرض جديدة
  قبل معرفة إن كان RTL يُقرأ جيدا
  عمل بلا قياس.

- **النتيجة: أ يفوز 5-0 بالإجماع.**
  أول خطوة: اختبار قراءة RTL على
  مثال البرنامج الكامل في الملعب.

## نموذج صيغة RTL — التعيين المعكوس (2026-11-05، محلي فقط، بلا دفع)

- **الأمر:** «ابدأ يا بطل» — بعد اجتماع
  21 (ج مفتوح كخطوة لاحقة).
- **النموذج:** التعيين المعكوس
  «قيمة = اسم» (مثال `٥ = س`)،
  إضافة لا استبدال، والصيغة
  العادية تبقى. وفي
  parse_assign_or_expr: حين
  الطرف الأيسر ليس هدفا صالحا
  (ليس اسما ولا فهرسة ولا نقطة)

  ثم نهاية جملة، يُبنى نفس عقدة
  التعيين (الهدف الاسم، والقيمة
  التعبير) — فيعمل المفسر وVM
  وREPL بلا تغيير فيهم. و«س = ص»
  تبقى تعيينا عاديا (الهدف س)
  لأن الطرف الأيسر اسم.
- **الحدود:** الطرف الأيمن اسم
  مفرد فقط (`٥ = قائمة[٠]` خطأ
  «هدف التعيين غير صالح»)؛ ولا
  تسلسل (`٥ = س = ص` خطأ)؛ ولا
  تعليق نوعي معكوس.

  أخضر (منها اختبار النموذج:
  معكوس + عادي + قيمة دالة +
  الحد + --vm)؛ والتشغيل الأصلي
  يطبع ٨ / س أكبر / ١٤؛ وREPL
  يقبل `٥ = س` ويطبع ٥.
- **الحكم معلق:** البرنامج عُرض
  على صاحب اللغة في المحادثة
  ليحكم على القراءة (أي
  الصيغتين أطبيعية من اليمين؟)
  — والنموذج لم يُدفع للعام،
