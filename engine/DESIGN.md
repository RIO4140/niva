# تصميم محرك Rio المستقل (v1) — ملف محلي فقط، لا يدفع للمستودع العام

هذا الملف خطة عمل داخلية بين صاحب اللغة ومساعده،
وليس وثيقة للعميل. المستودع العام يحمل الكود
والأمثلة وREADME بسيطة فقط، بدون هذا الملف.

لغة التنفيذ: Rust.
المحلل: Lexer + Parser.
التمثيل الوسيط: AST.
التنفيذ: Tree-Walking Interpreter.
اللغة الأساسية: العربية.
الملفات: ‎.rio.
التشغيل: محلي دون Python.
الأنظمة المستهدفة: Windows وLinux وAndroid.
ملحوظة: لا يوجد Compiler يحوّل إلى لغة آلة في v1. الـ Interpreter
المكتوب بـ Rust كافٍ ليكون محرك تنفيذ مستقلا. الكود هنا std فقط
(لا مكتبات خارجية)، وهو محمول، فيمكن بناؤه لـ Windows وLinux وAndroid،
لكن النسخة المبنية هنا هي Linux، وبناء Windows (عبر mingw) وAndroid
(عبر NDK) خطوة إصدار لاحقة، وليست مدعاة هنا.

## 1. AST — شجرة التمثيل المجردة

كل عقدة تحمل السطر والعمود. الأنواع (في `src/ast.rs`):

أوامر (Stmt):
- تعيين: متغير، أو عنصر في قائمة/قاموس
- طباعة: `اطبع` مع قائمة تعبيرات
- شرط: `إذا` مع فروع `وإلا إذا` وفرع `وإلا`
- حلقة: `بينما`، و`لكل ... في ...`
- تكرار: `كرر N مرات`، و`كرر طالما شرط`
- تعريف دالة: `دالة` مع معاملات وجسم
- إرجاع: `ارجع` مع قيمة اختيارية
- كسر ومتابعة: `اكسر`، `تابع`، و`مرر` (لا شيء)
- محاولة: `حاول` مع `ماعدا` و/أو `أخيرا`
- جملة تعبير: استدعاء دالة وحده في سطر

تعبيرات (Expr):
- عدد، نص، منطقي (`صحيح`/`خطأ`)، `لاشيء`
- اسم متغير
- قائمة `[a، b]`، وقاموس `{"مفتاح": قيمة}`
- ثنائي: `+ - * / % == != < > <= >= و أو في ليس في`
- أحادي: سالب، و`ليس`
- استدعاء: دالة أو دالة مدمجة مع معاملات
- فهرسة: `قائمة[0]`، `قاموس["مفتاح"]`، `نص[0]`

أولوية التعبيرات: `أو` ثم `و` ثم المقارنة ثم الجمع/الطرح
ثم الضرب/القسمة ثم الأحادي ثم الأساسي (مع الاستدعاء والفهرسة).

الكتل: نقطتان `:` ثم سطور بمسافة بادئة (مثل Python)،
أو جملة واحدة على نفس السطر بعد النقطتين.

## 2. Scope — نطاق المتغيرات

- النطاق العام هو النطاق السفلي.
- استدعاء الدالة يفتح نطاقا جديدا. المعاملات والمتغيرات المعينة
  داخل الدالة محلية فقط، وتختفي عند عودة الدالة.
  **متغير داخل الدالة غير متاح خارجها.**
- قراءة المتغير تبحث من النطاق الداخلي إلى الخارج حتى النطاق العام،
  فالدالة تقرأ المتغيرات العامة، لكن تعيينها داخل الدالة لا يغير
  متغيرا عاما بنفس الاسم (ينشئ متغيرا محليا).
  الاستثناء الوحيد: تعيين عنصر في قائمة أو قاموس موجود يعدّل
  الكائن نفسه، أينما كان.
- `إذا` و`بينما` و`لكل` و`كرر` **لا تفتح نطاقا**.
  **متغير داخل الحلقة أو الشرط متاح بعدها في نفس النطاق،**
  ومتغير الحلقة نفسه (`لكل رقم في ...`) يبقى بعد الحلقة
  بقيمته الأخيرة. هذا مقصود، لأنه يسمح بالتجميع داخل الحلقة
  واستخدام النتيجة بعدها.

## 3. Type System — نظام الأنواع

اللغة ديناميكية الأنواع: المتغير قد يحمل أي نوع، وقد يعاد تعيينه
إلى نوع آخر، لكن كل عملية تفحص الأنواع وقت التشغيل، ولا يوجد
تحويل ضمني صامت.

الأنواع: عدد، نص، منطقي، قائمة، قاموس، لاشيء، دالة.

قواعد العمليات:
- `+`: عدد+عدد، نص+نص (دمج)، قائمة+قائمة (دمج). غير ذلك خطأ نوع.
- `- * / %`: عددان فقط. القسمة أو باقي القسمة على صفر خطأ وقت تشغيل.
- `== !=`: أي نوعين، والمساواة بالقيمة. نوعان مختلفان غير متساويين.
- `< > <= >=`: عددان، أو نصان (ترتيب معجمي). غير ذلك خطأ نوع.
- `و أو`: منطقيان فقط، مع اختصار (short-circuit).
- `ليس`: منطقي فقط.
- `في` / `ليس في`: عنصر في قائمة، أو نص جزئي في نص،
  أو مفتاح نصي في قاموس. غير ذلك خطأ نوع.
- شرط `إذا` و`بينما` و`كرر طالما` يجب أن يكون منطقيا،
  وليس عددا. الرقم 1 ليس صحيحا هنا.
- فهرسة القائمة: عدد صحيح داخل النطاق. فهرسة القاموس: نص
  موجود. فهرسة النص: عدد صحيح داخل النطاق.
- استدعاء الدالة: عدد المعاملات يجب أن يطابق التعريف.

التحويل الصريح (دوال مدمجة):
- `عدد(x)`: عدد كما هو، منطقي إلى 1/0، نص رقمي إلى عدد،
  غير ذلك خطأ نوع. النص غير الرقمي خطأ نوع.
- `نص(x)`: أي قيمة إلى نصها المطبوع. المنطقي إلى "صحيح"/"خطأ".
- `نوع(x)`: اسم النوع بالعربي: عدد، نص، منطقي، قائمة،
  قاموس، لاشيء، دالة.

دوال مدمجة أخرى: `طول`، `مدى`، `مجموع`، `أدنى`، `أقصى`،
`مطلق`، `اقرأ_ملف`، `اكتب_ملف`، `ادخل` (اختياري مع سؤال نصي).

## 4. Error Handling — رسائل الأخطاء

كل خطأ عربي، ويتضمن السطر والعمود ونوع الخطأ، بالصيغة:
`خطأ <النوع>: <الرسالة> (السطر X، العمود Y)`

أنواع الأخطاء:
- لغوي: حرف غير معروف، نص غير مغلق، مسافة بادئة غير متوقعة.
- نحوي: تعبير غير متوقع، توقع قوس أو نقطتين، كتلة فارغة،
  هدف تعيين غير صالح، فئة أو استيراد (غير مدعوم في v1).
- نوع: جمع نص وعدد، شرط غير منطقي، فهرس غير عدد،
  استدعاء قيمة ليست دالة، تحويل غير صالح.
- وقت التشغيل: متغير غير معرف، دالة غير معرفة، قسمة على صفر،
  فهرس أو مفتاح خارج النطاق، عدد معاملات غير صحيح،
  ارجع/اكسر/تابع خارج سياقه، تجاوز حد التكرار.
- إدخال/إخراج: تعذر قراءة أو كتابة ملف، وتعذر قراءة الإدخال.

أمثلة:
- `خطأ نوع: لا يمكن جمع نص وعدد (السطر 2، العمود 10)`
- `خطأ وقت التشغيل: متغير غير معرف: نتيجة (السطر 5، العمود 7)`
- `خطأ وقت التشغيل: قسمة على صفر (السطر 3، العمود 12)`

## 5. ما هو خارج v1

- الفئات (`فئة`): المحلل يرفضها برسالة واضحة،
  لأنها تحتاج تصميم كائنات، وليست جزءا من
  النواة في v1.
- الوصول بالنقطة لغير الوحدات (مثل `قاموس.values()`):
  خطأ نوع في التنفيذ، لأن النقطة في هذه المرحلة
  للوحدات فقط (انظر §7).
- لا Compiler إلى لغة آلة في v1.
  الـ Interpreter كافٍ، والملف التنفيذي الناتج من Rust
  مستقل بذاته.

## 6. Phase 1A — الخطوة 1: المحلل الدلالي (منفذة 2026-11-05)

بعد اعتماد v1.3، بدأ تنفيذ Phase 1A بالخطوة 1:
محلل دلالي (`src/semantic.rs`) يعمل بعد التحليل
النحوي وقبل التنفيذ، ولا يغير دلالة اللغة.

ما يفحصه:
- قراءة متغير غير معرف في أي نطاق مرئي.
- `ارجع` خارج دالة، و`اكسر`/`تابع` خارج حلقة
  (حلقة خارج دالة لا تحسب لداخل دالة متداخلة).
- استدعاء دالة مستخدم معروفة أو دالة مدمجة
  بعدد معاملات خاطئ.
- معاملات مكررة في تعريف دالة، وهدف تعيين
  غير صالح (غير اسم أو اسم[فهرس]).

قواعد النطاق تطابق المفسر تماما: الدالة تفتح
نطاقا جديدا، والكتل لا تفتح نطاقا، ومتغير
الحلقة يبقى بعدها، واسم الدالة يضاف قبل
جسمها (للاستدعاء الذاتي)، والاستدعاء قبل
التعريف يفشل، كما في التنفيذ من أعلى لأسفل.

نوع خطأ جديد: `دلالي`، بصيغة:
`خطأ دلالي: متغير غير معرف: س (السطر X، العمود Y)`.
إذا فشل التحليل الدلالي، لا يعمل البرنامج
أبدا، فلا طباعة ولا كتابة ملف تحدث قبل الخطأ.

ما لا يفحصه بعد (خطوات 1A لاحقة، لا هذه):
الأنواع التدريجية، والفئات/الواجهات.
الوحدات/الاستيراد والوصول بالنقطة للوحدات
صارتا منفذتين في الخطوة 2 (§7)، لا في هذه.

## 7. Phase 1A — الخطوة 2: الوحدات والاستيراد (منفذة 2026-11-05)

صيغ الاستيراد الثلاث:
- `استورد وحدة` — يربط قيمة وحدة باسمها.
- `استورد وحدة باسم مختصر` — يربط قيمة وحدة
  بالاسم المختصر.
- `من وحدة استورد اسم1، اسم2` — يربط كل اسم
  مباشرة، من صادرات الوحدة.

`صدّر اسم1، اسم2` يعلن أسماء عامة لملف الوحدة.
قاعدة صارمة: الأسماء غير المصدرة خاصة بالوحدة،
واستيرادها أو الوصول إليها بالنقطة يفشل بخطأ
يذكر اسم الوحدة والاسم، ويقترح إضافة `صدّر`.
وحدة بلا أي `صدّر` لا تصدر شيئا.

حل الوحدات:
- اسم الوحدة معرف فقط، لا مسار، فلا عبور مسارات
  عبر اسم وحدة.
- الملف هو `<اسم الوحدة>.rio` في مجلد البرنامج
  الرئيسي، لا في مجلد العمل الحالي.
- تحميل مرة واحدة في كل تشغيل: استيراد ثانٍ
  لنفس الوحدة يرجع القيمة المخزنة، ولا يعيد
  تنفيذ ملفها (ولا طباعته) مرة ثانية.
- استيراد دائري يفشل بخطأ يذكر سلسلة الدورة.

نطاق دوال الوحدة:
- ملف الوحدة ينفذ في نطاق عام جديد، معزول
  عن نطاق المتصل، ثم يحتفظ بنطاقه الكامل
  (بما فيه الأسماء الخاصة) لاستدعاءات دواله.
- دالة معرفة في أعلى ملف الوحدة، عند استدعائها
  من خارج الوحدة، تدفع نطاق وحدتها تحت نطاق
  استدعائها، فتقرأ ثوابت الوحدة وتستدعي
  مساعديها الخاصين. هذا يشمل الاستدعاء عبر
  النقطة، وعبر `من ... استورد`، وعبر اسم مستعار
  لدالة وحدة، لأن الدالة تحمل اسم وحدتها.
- حدود هذه المرحلة، موثقة لا مخفية:
  - ملفات الوحدات لا تمر بالمحلل الدلالي قبل
    التنفيذ (البرنامج الرئيسي فقط يمر به).
    أخطاء الوحدة تظهر وقت التنفيذ، مع اسم
    الوحدة في الرسالة.
  - عضو الوحدة لا يفحص دلاليا في البرنامج
    الرئيسي؛ وجوده وتصديره يفحصان وقت التنفيذ.
  - تعديل فهرسي لمتغير عام في الوحدة من داخل
    دالة وحدة لا يستمر عبر الاستدعاءات في هذه
    المرحلة (النطاق المدفوع نسخة من نطاق الوحدة
    بعد تحميلها).
  - دالة وحدة يمكنها رؤية متغيرات المتصل
    العامة، لأن نطاق الوحدة يدفع فوق نطاقات
    المتصل، لا بدلا منها. عزل كامل بالنطاقات
    المغلقة خطوة لاحقة، لا هذه.
- الوصول بالنقطة: `وحدة.اسم` يرجع الاسم من
  صادرات الوحدة فقط. على أي نوع آخر، خطأ نوع:
  الوصول بالنقطة مدعوم على الوحدات فقط في
  هذه المرحلة.
- قيمة الوحدة: نوعها `وحدة`، وطباعتها
  `<وحدة الاسم>`.

## 8. Phase 1A — الخطوة 3: الأنواع التدريجية (منفذة 2026-11-05)

الأنواع المعروفة: عدد، نص، منطقي، قائمة، قاموس،
لاشيء، دالة، وحدة، وأي (أي = أي نوع، بلا فحص).
نوع غير معروف في التعليق خطأ نحوي.

صيغة التعليق:
- متغير: `س: عدد = ٥`
- معامل دالة: `دالة جمع(أ: عدد، ب: عدد): عدد:`
- نوع إرجاع الدالة بعد قوس المعاملات، ثم نقطتان
  لبداية الكتلة، كما في المثال السابق.
- التعليق اختياري دائما: برنامج بلا تعليقات
  يعمل كما كان، بلا أي فحص نوعي جديد.
- التعليق مسموح لمتغير فقط، لا لفهرسة:
  `س[٠]: عدد = ٥` مرفوض نحوياً.
- `س: عدد` بلا تعيين مرفوض نحوياً: التعليق
  يتطلب تعيينا في نفس الجملة.

فحص دلالي (البرنامج الرئيسي فقط، قبل التنفيذ):
- قيمة معروفة النوع لا تطابق نوع المتغير المعلن،
  أو معامل الدالة المعلن، أو نوع إرجاع الدالة
  المعلن، خطأ دلالي، ولا يعمل البرنامج أبدا،
  فلا طباعة تحدث قبل الخطأ.
- نوع غير معروف (متغير بلا تعليق، فهرسة، نقطة،
  عملية بنوع غير معروف، استدعاء دالة بلا نوع
  إرجاع معلن) يمر دلاليا دائما: التدرج، لا رفض
  كاذب.
- إعادة تعيين متغير معلن في نفس النطاق يجب أن
  تطابق نوعه المعلن، حتى بلا تعليق جديد.
  التعيين داخل دالة يعرف متغيرا محليا جديدا،
  يخفي أي متغير خارجي بنفس الاسم، ولا يفحص
  ضد نوع الخارجي.
- إرجاع بلا قيمة نوعه لاشيء، ويفحص ضد نوع
  الإرجاع المعلن، إن وجد.

فحص وقت التنفيذ (المفسر، للرئيسي والوحدات):
- تعيين معلق يفحص قيمة التنفيذ الفعلية ضد
  التعليق، حتى لو كانت القيمة من متغير بلا نوع.
  هذا يمسك حالات التدرج التي يمررها الفحص
  الدلالي، بعد طباعة سابقة إن وجدت (خطأ نوع،
  لا دلالي).
- استدعاء دالة يفحص كل معامل ضد نوعه المعلن،
  ونوع الإرجاع الفعلي ضد نوع الإرجاع المعلن.
  دالة معلن إرجاعها عدد، ولم ترجع شيئا صراحة،
  خطأ نوع وقت التنفيذ، لا لاشيء صامت.
- `أي` لا يفحص أبدا، دلاليا ولا وقت التنفيذ.

أنواع معروفة استنتاجيا في الفحص الدلالي:
- حرفي: عدد، نص، منطقي، لاشيء، قائمة، قاموس.
- متغير معلن، ودالة معروفة (نوعها دالة)، ووحدة
  مستوردة (نوعها وحدة).
- استدعاء دالة مدمجة: طول/مجموع/مطلق/عدد = عدد،
  نص/نوع/اقرأ_ملف/ادخل = نص، مدى = قائمة،
  اكتب_ملف = لاشيء. أدنى/أقصى غير معروف.
- مقارنة ومنطق وعضوية = منطقي. جمع بمعاملين
  من نفس النوع عدد/نص/قائمة = ذلك النوع.
  طرح/ضرب/قسمة/باقي بعددين = عدد. سالب لعدد
  = عدد. ليس لمنطقي = منطقي. غير ذلك غير معروف.

حدود هذه المرحلة، موثقة لا مخفية:
- لا أنواع عامة لعناصر القائمة/القاموس:
  قائمة تعني أي قائمة، بلا فحص عناصر.
- لا فحص نوعي لعمليات ثنائية وقت التحليل،
  عدا الاستنتاج أعلاه للتعليقات: عملية بنوعين
  غير متطابقين تفشل وقت التنفيذ، كما كانت.
- ملفات الوحدات لا تمر بالفحص الدلالي، لكن
  تعليقاتها ومعاملات دوالها تفحص وقت التنفيذ
  كما أعلاه، لأن المفسر يفحصها عند التنفيذ.
- دالة وحدة مستدعاة عبر النقطة لا تفحص
  معاملاتها دلاليا في الرئيسي (عضو الوحدة
  غير معروف دلاليا)، لكنها تفحص وقت التنفيذ.
- ما لم ينفذ بعد في 1A: الفئات/الواجهات فقط.

## 9. Phase 1A — الخطوة 4: فئات بسيطة (منفذة 2026-11-05)

الصيغة، بالمصطلحات المصوت عليها في الاجتماع 1:
- تعريف: `فئة نقطة:` + كتلة دوال فقط.
- إنشاء: `أنشئ نقطة(٣، ٤)`، ولا يستدعى اسم
  الفئة مباشرة كدالة (خطأ يرشد إلى أنشئ).
- المنشئ: طريقة باسم أنشئ داخل الفئة، تستدعى
  تلقائيا عند الإنشاء، ومعاملاتها هي معاملات
  الإنشاء فقط.
- نفس: متغير خاص مربوط تلقائيا بالكائن داخل
  أي طريقة، وليس معاملا، ولا يكتب كمعامل
  (خطأ نحوي إن كتب).
- الطرق: دوال عادية داخل الفئة، بمعاملاتها
  وأنواعها الاختيارية كما في الدوال العادية.
- الحقول: تنشأ ديناميكيا بالتعيين بالنقطة،
  عادة في المنشئ: `نفس.س = س`. لا إعلان حقول
  في جسم الفئة في هذه المرحلة.
- الوصول: بالنقطة، كما في الوحدات: حقل أولا،
  ثم طريقة (مربوطة بالكائن)، ثم خطأ وقت
  تشغيل إن لم يوجد الاسم.
- الطباعة: فئة `<فئة اسم>`، وكائن `<كائن اسم>`.
- الأنواع: فئة نوعها فئة، وكائن نوعه كائن،
  وكلاهما اسم نوع معروف في التعليقات.
  إنشاء كائن نوعه كائن دلاليا.

التنفيذ:
- Value::Class(Rc<ClassData>) وValue::Instance
  (Rc<InstanceData>)، وحقول الكائن خلف Rc،
  فنسخ قيمة الكائن تشارك الحقول، وتعديل
  نفس.حقل داخل طريقة يبقى بعد عودة الطريقة،
  لأي شكل هدف (متغير، نفس، نقطة متسلسلة،
  عنصر قائمة/قاموس).
- Value::BoundMethod: طريقة مربوطة بكائن،
  تنتج من تقييم ك.طريقة، واستدعاؤها يربط
  نفس تلقائيا. مساواة الفئات/الكائنات بالهوية
  (نفس Rc)، لا بمقارنة الحقول العميقة.
- المحلل الدلالي: اسم الفئة معرف بنوع فئة،
  وأجسام الطرق تحلل بنطاق جديد فيه نفس
  بنوع كائن، ومعاملات الطريقة، وارجع مسموح
  داخل الطريقة، وحلقة الطريقة لا تسري خارجها.
  إنشاء فئة غير معرفة خطأ دلالي قبل التنفيذ.
  ملفات الوحدات لا تمر بالمحلل الدلالي، لكن
  فئاتها تنفذ كما في الرئيسي.

حدود هذه المرحلة، موثقة لا مخفية:
- لا وراثة (ورث) ولا واجهات (واجهة) بعد، رغم
  تصويت المصطلحات عليهما في الاجتماع 1؛
  هما المرحلة التالية، لا هذه المرحلة.
- لا حقول معلنة في جسم الفئة، ولا حقول خاصة،
  ولا طرق ثابتة؛ كل الحقول عامة وديناميكية.
- لا فئات متداخلة: جسم الفئة دوال فقط.
- حقل يظلل طريقة بنفس الاسم يفوز عند القراءة.
- استدعاء طريقة مخزنة في متغير (م = ك.طريقة)
  يعمل لأنها BoundMethod، وتحمل الكائن معها.
- إصلاح جانبي اكتشف أثناء التنفيذ: كلمة فئة
  لم تكن تصل للمحلل أصلا، لأن تطبيعها (ئ→ي،
  ة→ه) يعطي فيه، بينما خريطة الكلمات كانت
  تطابق فئه فقط؛ أضيفت فيه إلى الخريطة.
  واسم طريقة المنشئ أنشئ كلمة محجوزة، فقبل
  في محلل الدوال صراحة كاسم طريقة.

## 10. Phase 1A — الخطوة 5: وراثة وواجهات (منفذة 2026-11-05)

بناء على فوز التصويت في الاجتماع 2 (عرض RTL
فقط، بلا تغيير في الصيغة): صيغة المحرك بقيت
LTR كما هي، ولم يعكس أي ترتيب رموز. هذا
القسم يضيف الوراثة والواجهات فقط، بنفس
الصيغة LTR.

الوراثة:
- `فئة طالب ورث شخص:` — الأب يجب أن يكون
  معرفا قبل الابن (خطأ دلالي إن لم يكن).
- البحث عن طريقة: طرق الابن أولا، ثم سلسلة
  الأب تكراريا. التجاوز يعمل لأن طريقة الابن
  تفوز. نفس داخل طريقة موروثة يربط بكائن
  الابن، لا بكائن أب منفصل.
- المنشئ: البحث عن أنشئ يمشي في السلسلة
  أيضا. ابن بلا أنشئ يرث منشئ أبيه تلقائيا
  بنفس المعاملات. ابن بأنشئ خاص لا يستدعي
  منشئ أبيه تلقائيا؛ هو مسؤول عن كل الحقول.
- الحقول ديناميكية على الكائن، فلا وراثة حقول
  منفصلة عن المنشئ.

الواجهات:
- تعريف: `واجهة اسم:` + توقيعات دوال فقط،
  كل طريقة جسمها مرر فقط، وإلا خطأ نحوي.
  التوقيع المخزن هو (اسم الطريقة، عدد المعاملات).
- تنفيذ: `فئة اسم واجهة و1، و2:`، أو مع ورث:
  `فئة اسم ورث أب واجهة و1:`، بالترتيب الثابت
  ورث ثم واجهة.
- الفحص عند تعريف الفئة (وقت التشغيل):
  كل طريقة مطلوبة يجب أن توجد (خاصة أو
  موروثة) وبعدد المعاملات الصحيح، وإلا خطأ
  وقت تشغيل يسمي الفئة والطريقة والواجهة.
  v1 يفحص الوجود والعدد فقط، لا أنواع المعاملات
  ولا نوع الإرجاع.
- نوع الواجهة: واجهة، وطباعتها `<واجهة اسم>`.

إصلاح جانبي في هذه الخطوة:
- عمق استدعاء 100 في الاختبارات بدأ يفيض
  مكدس Rust في بناء التصحيح بعد اتساع AST
  بالفئات/الواجهات، رغم أن حد Rio هو 200.
  الحل: تشغيل المحرك في خيط بمكدس 64 MB
  في main.rs، فيعيد ضمان أن حد Rio هو ما
  يوقف الاستدعاء الذاتي، لا فيض مكدس Rust،
  في بناء التصحيح والإصدار معا. الاختبارات
  عادت كلها تمر بعد الإصلاح.

- فئة معرفة داخل طريقة لا تتسرب للمتصل:
  خريطة الفئات تنسخ لابن VM وتضيع عند
  الرجوع، مثل نطاق المفسر.
- فروق معروفة: أنواع معاملات الطرق لا
  تفحص وقت التشغيل في VM (مثل الدوال
  العادية)؛ ومتغير معيّن بعد تعريف دالة
  ثم استدعاؤه يشغل الدالة في VM ويخطئ
  في المفسر.
- غير المدعوم: الوحدات (استورد، صدّر،
  نقطة الوحدات) — شريحة لاحقة.

## 18. الخطوة 1 — الـ closures والتعيين المعجمي (منفذة 2026-11-05)

بناء على ترتيب الاجتماع 10 (اعتماد
ترتيب التحليل الخارجي) وقرار الاجتماع
11 (التعيين المعجمي 3-1-1).

التصميم:
- كل نطاق هو `Rc<RefCell<HashMap>>`
  مشترك. قيمة الدالة تحمل `captured`:
  سلسلة النطاقات وقت التعريف، كمؤشرات
  مشتركة (لا نسخة)، فالدالة المرجعة
  ترى بيئتها وتعدلها.
- استدعاء دالة (أو طريقة) بلا وحدة
  يستبدل مكدس النطاقات بالسلسلة
  الملتقطة، يدفع نطاق المعاملات، ثم
  يعيد مكدس المتصل بعد التنفيذ — حتى
  عند الخطأ. الاستدعاء الذاتي يعمل لأن
  الاسم يعرف في نفس النطاق الملتقط
  (مشارك)، فيرى نفسه.
- التعيين المعجمي (Meeting 11): `س =
  قيمة` يعين لأقرب ربط موجود (يمشي
  السلسلة)، ويعرف محليا فقط إذا لم
  يوجد الاسم في أي مكان. هذا ما يجعل
  العداد يعمل (1، 2، 3) وعدادين من نفس
  المصنع مستقلين. متغير يعرف لأول مرة
  داخل دالة ما زال لا يخرج منها،
  ومتغير الحلقة ما زال يعرف في النطاق
  الحالي فقط (لا يعدل عاما بنفس الاسم).
- المحلل الدلالي يطابق القاعدة: التعيين
  لاسم خارجي لا يعرف محليا جديدا،
  ويفحص النوع المعلن في الربط الموجود؛
  وإعادة إعلان بنوع مختلف عن الخارجي
  خطأ دلالي.
- دوال الوحدات (module: Some) تبقى على
  دفع نطاق الوحدة (الخطوة 2) ولا تستخدم
  السلسلة الملتقطة. وclosure مخزنة في
  عام وحدة لا توسم كدالة وحدة (سلسلتها
  أطول من نطاق الوحدة وحده)، فتعمل
  بسلسلتها الملتقطة.
- الطرق تلتقط سلسلة وقت تعريف الفئة؛
  وطريقة معرفة داخل دالة تغلق على
  محلياتها. نفس يربط كالمعتاد.
- غير المدعوم: الـ closures في VM
  (وضع --vm يرفض الدالة المرجعة بخطأ
  عربي واضح، بلا انهيار) — شريحة لاحقة
  في الخطوة 4 من الخطة. ولا lambdas بعد
  (البند التالي في الخطوة 1).
- إصلاح REPL مصاحب: الكتل المتداخلة
  كانت تنقطع (المعجم يغلق الكتل عند
  EOF، فبادئة تنتهي داخل كتلة متداخلة
  كانت تفسر كمكتملة وتنفذ مبكرا).
  القاعدة الآن: سطر بمسافة بادئة أثناء
  كتلة معلقة ينتظر فقط، ولا ينهي الكتلة
  إلا سطر بلا مسافة أو أمر (الأمر ينهي
  الكتلة أولا ثم ينفذ). وتعبير منفرد في
  نهاية إدخال متعدد الجمل يطبع قيمته
  (تعريف دالة ثم استدعاؤها يطبع النتيجة).

## 19. التثبيت العربي وكل شيء عربي (منفذ 2026-11-05)

## 20. الـ lambdas (منفذ 2026-11-05)

بأمره «ابدأ» بعد الاجتماع 13
(صياغة 5-0 لـ `دالة_مجهولة(س): س + 1`).

- الصياغة: `دالة_مجهولة(معاملات): تعبير`
  واحد، إرجاع ضمني، بلا جسم كتلي في
  v1. والمعاملات تقبل نفس أنواع الدوال
  المسماة (`س: عدد`) اتساقا. والـ lambda
  قيمة دالة كاملة: تلتقط معجميا، تمرر
  كوسيط، ترجع من دالة، تستدعى فورا
  بأقواس `(دالة_مجهولة(س): س + 1)(10)`،
  وتتداخل (currying).
- التنفيذ: تعبير جديد `Lambda` في AST؛
  والمفسر يخزنها كقيمة `Function`
  اسمها «مجهولة» وجسمها جملة `ارجع`
  واحدة للتعبير، فيعيد `call_user`
  استخدام كل آلة الـ closures (الالتقاط،
  أنواع المعاملات، حد العمق، قيمة
  الإرجاع). والمحلل الدلالي يحلل
  الجسم في نطاق معاملات جديد مع
  النطاقات المحيطة ظاهرة (الالتقاط)،
  ونوع الـ lambda المستنتج `دالة`،
  والمعامل المكرر خطأ دلالي.
- الحدود المقصودة: الـ lambda لا تستطيع
  الإسناد (الإسناد جملة لا تعبير)،
  فتقرأ المتغيرات الملتقطة ولا تعدلها
  مباشرة؛ ومن يحتاج تعديلا يستخدم
  دالة مسماة أو يستدعي دالة مسماة
  تعدل. وفي `--vm` ترفض بخطأ عربي
  واضح (مفسر فقط حتى الخطوة 4)،
  كالـ closures المرجعة. و`اطبع (...)`
  شكل أقواس خاص في `اطبع`، فالاستدعاء
  الفوري داخل `اطبع` يحتاج إسنادا أولا
  أو سياقا آخر (الاستدعاء نفسه يعمل
  في الإسناد والوسيط والشرط).

## 21. دوال النصوص والقوائم (منفذ 2026-11-05)

- الحدود: الطرق مفسر فقط؛ وفي `--vm`

  فقط») بلا عمل إضافي. والكتابة
  الرجعية لا تشمل هدف الفهرسة أو
  الحقل في v1.

## 22. حد عمق الاستدعاء 500 (منفذ 2026-11-05)

بأمره «اكمل شغلك يابطل» بعد
الاجتماع 15 (الخيار ب 4-1).

- الحد: `MAX_CALL_DEPTH = 500`، ثابت
  واحد مشترك بين المفسر والـ VM
  (كان 200 بهاردكود في موضعين بالـ VM).
  ورسالة الخطأ تطبع الحد من الثابت.
  والـ thread الذي يعمل عليه المفسر
  والـ VM والـ REPL صار 256MB (كان
  64MB)، بثابت واحد في main.rs.
- كيف تحدد الرقم (قياس لا تخمين):
  مع رفع الحد مؤقتا، على thread 64MB:
  خفيف release آمن 7000 وينهار 8000،
  وثقيل release آمن 3000 وينهار 4000،
  وخفيف debug آمن 800 وينهار 900،
  وثقيل debug آمن 350 وينهار 400،
  ومتطرف (10 محليات + تعبير واسع)
  debug آمن 175 وينهار 190، وrelease
  آمن 1000 وينهار 2000. فالحد 200
  نفسه كان غير آمن في debug للإطار
  المتطرف (العمق 191 ينهار قبل أن
  يرفض الحد شيئا)، وإزالة الحد انهيار
  مؤكد (exit 134). وبـ 256MB تتضاعف
  السقوف ~4x، فالـ 500 تحمل ~30%
  هامشا على أسوأ شكل مقاس.
- التحقق: العمق 500 يكمل (حتى الشكل
  المتطرف) والعمق 501 خطأ Niva نظيف
  «تجاوز حد عمق الاستدعاء (500)»،
  في release وdebug، وفي المفسر والـ VM
  والـ REPL. واختبارات حدودية دائمة
  في التكامل تثبت ذلك على ثنائي debug
  (الحالة الأسوأ).

## 28. إصلاح CI على Windows وmacOS (2026-11-05)

أول تشغيل CI على GitHub (بعد دفعة
53477589) فشل على Windows وmacOS
ونجح على Linux. والسبب اختباران في
`permissions.rs`، لا في المنطق الأمني:

- `resolve` كان يعيد المسار بعد
  التحويل القانوني (canonicalize):
  على macOS يعيد `/private/tmp/...`
  (لأن `/tmp` رابط رمزي)، وعلى Windows
  يعيد `\\?\D:\...`. والفحص الأمني
  نفسه كان صحيحا، لكن العقد المكسور
  هو قيمة الإرجاع. والإصلاح: التحويل
  القانوني للفحص فقط، والإرجاع هو
  المسار المعجمي الذي سماه البرنامج.
  واختبار انحدار جديد
  (`resolve_returns_lexical_path_not_canonical`)
  يعيد إنتاج الخلل على Linux أيضا عبر
  قاعدة مرموزة، وثبت أنه يفشل بالكود
  القديم وينجح بالجديد.
- اختبار `symlink_escape_rejected` كان
  ينشئ الرابط الرمزي تحت `#[cfg(unix)]`
  فقط، فعلى Windows لم يكن هناك رابط
  أصلا والادعاء يفشل فراغا. والإصلاح:
  إنشاؤه على Windows أيضا
  (`symlink_dir`)، وتخطّي الاختبار إن
  تعذر إنشاؤه (بلا امتياز) بدلا من
  الفشل على غياب لم يصنعه.
- التحقق: الاختبارات محليا 70+45
  خضراء؛ ودفعة 2050bd4e جعلت CI أخضر
  على المنصات الثلاث.

## 30. إصلاح مصيدة SystemTime في WASM (2026-11-05)

### 39.1 ما يعنيه «مترجم لا مفسر» — التعريف المعتمد

- **المترجم:** المصدر يُترجم مرة
  واحدة (AST ← بايت كود) قبل أي
  تنفيذ؛ ولا مصدر يُفسَّر وقت
  التشغيل؛ والبرنامج المسلَّم
  ملف تنفيذي مستقل يعمل وحده
  (بايت كود + محرك VM مضمّن فيه)،
  يبنيه `نيفا ابنِ برنامج.نيفا`.
- **ما يتوقف:** المفسر الذي يمشي
  الشجرة يتوقف عن كونه محرك
  تنفيذ البرامج؛ ويبقى مرجعا
  خفيا للتشخيص والمطابقة (39.3).
- **صراحة لا تخفى:** حلقة تنفيذ
  VM هي تقنيا مفسر بايت كود؛
  والفرق الجوهري هو أن المصدر
  يُترجم مسبقا ولا يُقرأ وقت
  التشغيل، وأن الناتج ثنائي
  مستقل. والهدف الحرفي (كود
  آلة أصلي) لم يُلغَ، بل رُتّب
  كمرحلة ك-3 (39.4)، لا كأول
  خطوة. وصاحب اللغة يحتفظ
  بالنقض: إن قرأ هذا وقال «لا،
  أقصد كود آلة الآن» صار خلفية
  C أولوية.

### 39.3 س2: مصير المفسر وREPL — الفائز ج 5-0

- **الخيارات:** أ استبدال كامل
  (حذف المفسر؛ REPL على المترجم)؛
  ب بقاء المفسر لـ REPL والسكربتات
  (وضع مساو)؛ ج المفسر يصير وضع
  مرجع/تشخيص خفيا (`--مفسر`)،
  وREPL والسكربتات على المترجم،
  و`--افتراضي` يُزال حين تصير
  VM الافتراضية، والحذف الكامل
  مؤجل.
- **الأصوات (كلها ج):**
  - مصمم اللغة: دلالة واحدة
    للمستخدم؛ والمفسر يبقى
    مرجع الدلالة لمجموعة
    المطابقة، لا طريقا لتشغيل
    البرامج؛ وREPL يجب أن يعمل
    على المترجم وإلا علّم دلالة
    لا يملكها المترجم.
  - منفذ المحرك: الحذف الآن
    تراجع (فجوات VM: closures،
    وحدات، حاول، دوال ملفات)؛
    ومراحل: المفسر بديل حتى
    التكافؤ، ثم تشخيص فقط؛
    والحذف قرار لاحق منفصل.
  - تجربة المبتدئ: النتيجة
    الظاهرة للمستخدم مطابقة
    لأ (محرك واحد)؛ وREPL يبقى
    فوريا (تجميع البايت كود
    ميكروثوان) وأخطاؤه عربية.
  - التوافق والاستقرار: برامج
    تعمل اليوم يجب أن تبقى
    تعمل؛ والمفسر بديل حتى
    يثبت التكافؤ بمجموعة
    المطابقة.
  - الجودة والأمان: المفسر هو
    المرجع الذي تُقاس عليه
    صحة المترجم؛ وحذفه يدمر
    القدرة على إثبات صحة
    المترجم؛ وهو أيضا مرجع
    سلوك FilePolicy.
- **النتيجة: ج يفوز 5-0
  بالإجماع.** وباء صفر — لأنها
  تبقي المفسر محركا مساويا،
  وهو ما رفضه أمر صاحب اللغة.
- **التفاصيل المعتمدة:**
  - `--افتراضي` يبقى علما تجريبيا
    حتى تصير VM الافتراضية، ثم
    يُزال (لا معنى لعلم حين لا
    يوجد محرك بديل).
  - `--مفسر` علم تشخيص جديد:
    يشغّل مفسر الشجرة للتشخيص
    ومقارنة المطابقة فقط، ولا
    يوثَّق كطريق لتشغيل البرامج.
  - REPL ينتقل إلى المترجم في
    مرحلة ك-2: كل كتلة تُترجم
    إلى بايت كود وتعمل على VM،
    مع نسخة VM دائمة وجدول
    عموميات يبقى عبر استدعاءات
    `feed()`، فتبقى حالة الجلسة.
  - الحذف الكامل للمفسر من
    الشجرة قرار لاحق منفصل،
    بعد إثبات المترجم، لا في
    هذا الاجتماع.

### 39.5 المراحل (مراحل فقط، لا تواريخ ولا وعود)

**ك-1 — تكافؤ المترجم (VM تصل إلى
ما يصل إليه المفسر)، بترتيب
الاعتماديات:**
1. Closures + lambdas + طرق
   النصوص/القوائم في VM
   (الاجتماع 11: التعيين
   المعجمي؛ الاجتماع 13: صياغة
   الـ lambda؛ الاجتماع 14:
   المجموعة) — أكبر فجوة دلالية،
   وكل ما بعدها يبنى على نموذج
   الإطارات.
2. إكمال التحكم: لكل، كرر،
   اكسر، تابع، حاول/ماعدا/
   أخيرا، في.
3. الوحدات + المكتبة في VM:
   استورد/صدّر/نقطة، والوحدات
   الأصلية الأربع (رياضيات،
   عشوائي، وقت، شبكة) — بما
   فيها اجلب بحدوده المعتمدة
   (HTTP أصلي فقط، وHTTPS خطأ
   عربي؛ §16).
4. دوال الملفات + ادخل في VM،
   مع ربط FilePolicy نفسه
   (شرط الاجتماع 8).
5. الحدود + بوابة المطابقة:
   عمق 500، وتكرار 1,000,000،
   وقياس fib(30)؛ وكل مثال وكل
   اختبار تكامل يعمل في الوضعين
   بمخرجات متطابقة — ولا انتقال
   إلى ك-2 قبل هذه البوابة.

**ك-2 — المترجم افتراضيا +
مصنوعات AOT:**
- VM تصير المحرك الافتراضي؛
  و`--افتراضي` يُزال؛ والمفسر
  يصير `--مفسر` (39.3).
- REPL ينتقل إلى المترجم
  (نسخة VM دائمة + جدول
  عموميات عبر `feed()`).
- `نيفا ابنِ برنامج.نيفا`:
  أولا مصنوع بايت كود محمول
  (يعمل بـ `نيفا شغّل`)، ثم
  الملف التنفيذي المستقل
  (بايت كود + وقت تشغيل VM
  مضمّن).
- قياس أداء منشور (fib(30))
  وتمرير تحسين VM (شرط
  الاجتماع 12).

**ك-3 — كود أصلي (خلفية C):**
- مولد كود C من AST (يعيد
  استخدام المحلل الدلالي
  نفسه)؛ ومكتبة وقت تشغيل C
  (قيم، جامع قمامة، دوال
  مدمجة، وحدات، فئات)؛ و
  `نيفا ابنِ --أصلي` ينتج
  ملفا تنفيذيا أصليا عبر cc
  النظام.
- شرط صلب: أخطاء cc تُترجم
  إلى أخطاء Niva عربية — لا
  تسرب لأي مخرجات cc
  إنجليزية إلى المستخدم.
- install.sh يتحقق من وجود cc
  ويخبر المستخدم بالعربي كيف
  يثبته (Termux: pkg install
  clang؛ Debian: apt install
  gcc؛ Windows: MinGW).
- خلفية C يجب أن تجتاز مجموعة
  المطابقة نفسها (مخرجات
  متطابقة).
- جامع القمامة التتبعي من
  v1.3 §6 يجب أن يوجد بحلول
  هذه المرحلة (مواصفته
  لآلة VM)؛ ووقت تشغيل C
  يحتاج جامعه الخاص أو تصميما
  مشتركا — نقطة تصميم في
  ك-3، لا قرار هنا.

**ك-4 — لاحقا:**
- Cranelift/LLVM (JIT) يعاد
  النظر فيه فقط إن ثبت قصور
  خلفية C.
- WASM كهدف للمترجم لاحقا
  (الملعب اليوم يشغّل المفسر
  مترجما إلى WASM؛ ومترجم
  Niva←WASM هدف منفصل).

### 39.6 شروط صلبة تسري على كل المراحل
