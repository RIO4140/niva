# تصميم محرك Rio المستقل (v1)

لغة التنفيذ: Rust.
المحلل: Lexer + Parser.
التمثيل الوسيط: AST.
التنفيذ: Tree-Walking Interpreter.
اللغة الأساسية: العربية.
الملفات: ‎.rio.
التشغيل: محلي دون Python.
الأنظمة المستهدفة: Windows وLinux وAndroid.
ملحوظة: لا يوجد Compiler يحوّل إلى لغة آلة في v1. الـ Interpreter
المكتوب بـ Rust كافٍ ليكون محرك تنفيذ مستقلا. الكود هنا std فقط
(لا مكتبات خارجية)، وهو محمول، فيمكن بناؤه لـ Windows وLinux وAndroid،
لكن النسخة المبنية هنا هي Linux، وبناء Windows (عبر mingw) وAndroid
(عبر NDK) خطوة إصدار لاحقة، وليست مدعاة هنا.

## 1. AST — شجرة التمثيل المجردة

كل عقدة تحمل السطر والعمود. الأنواع (في `src/ast.rs`):

أوامر (Stmt):
- تعيين: متغير، أو عنصر في قائمة/قاموس
- طباعة: `اطبع` مع قائمة تعبيرات
- شرط: `إذا` مع فروع `وإلا إذا` وفرع `وإلا`
- حلقة: `بينما`، و`لكل ... في ...`
- تكرار: `كرر N مرات`، و`كرر طالما شرط`
- تعريف دالة: `دالة` مع معاملات وجسم
- إرجاع: `ارجع` مع قيمة اختيارية
- كسر ومتابعة: `اكسر`، `تابع`، و`مرر` (لا شيء)
- محاولة: `حاول` مع `ماعدا` و/أو `أخيرا`
- جملة تعبير: استدعاء دالة وحده في سطر

تعبيرات (Expr):
- عدد، نص، منطقي (`صحيح`/`خطأ`)، `لاشيء`
- اسم متغير
- قائمة `[a، b]`، وقاموس `{"مفتاح": قيمة}`
- ثنائي: `+ - * / % == != < > <= >= و أو في ليس في`
- أحادي: سالب، و`ليس`
- استدعاء: دالة أو دالة مدمجة مع معاملات
- فهرسة: `قائمة[0]`، `قاموس["مفتاح"]`، `نص[0]`

أولوية التعبيرات: `أو` ثم `و` ثم المقارنة ثم الجمع/الطرح
ثم الضرب/القسمة ثم الأحادي ثم الأساسي (مع الاستدعاء والفهرسة).

الكتل: نقطتان `:` ثم سطور بمسافة بادئة (مثل Python)،
أو جملة واحدة على نفس السطر بعد النقطتين.

## 2. Scope — نطاق المتغيرات

- النطاق العام هو النطاق السفلي.
- استدعاء الدالة يفتح نطاقا جديدا. المعاملات والمتغيرات المعينة
  داخل الدالة محلية فقط، وتختفي عند عودة الدالة.
  **متغير داخل الدالة غير متاح خارجها.**
- قراءة المتغير تبحث من النطاق الداخلي إلى الخارج حتى النطاق العام،
  فالدالة تقرأ المتغيرات العامة، لكن تعيينها داخل الدالة لا يغير
  متغيرا عاما بنفس الاسم (ينشئ متغيرا محليا).
  الاستثناء الوحيد: تعيين عنصر في قائمة أو قاموس موجود يعدّل
  الكائن نفسه، أينما كان.
- `إذا` و`بينما` و`لكل` و`كرر` **لا تفتح نطاقا**.
  **متغير داخل الحلقة أو الشرط متاح بعدها في نفس النطاق،**
  ومتغير الحلقة نفسه (`لكل رقم في ...`) يبقى بعد الحلقة
  بقيمته الأخيرة. هذا مقصود، لأنه يسمح بالتجميع داخل الحلقة
  واستخدام النتيجة بعدها.

## 3. Type System — نظام الأنواع

اللغة ديناميكية الأنواع: المتغير قد يحمل أي نوع، وقد يعاد تعيينه
إلى نوع آخر، لكن كل عملية تفحص الأنواع وقت التشغيل، ولا يوجد
تحويل ضمني صامت.

الأنواع: عدد، نص، منطقي، قائمة، قاموس، لاشيء، دالة.

قواعد العمليات:
- `+`: عدد+عدد، نص+نص (دمج)، قائمة+قائمة (دمج). غير ذلك خطأ نوع.
- `- * / %`: عددان فقط. القسمة أو باقي القسمة على صفر خطأ وقت تشغيل.
- `== !=`: أي نوعين، والمساواة بالقيمة. نوعان مختلفان غير متساويين.
- `< > <= >=`: عددان، أو نصان (ترتيب معجمي). غير ذلك خطأ نوع.
- `و أو`: منطقيان فقط، مع اختصار (short-circuit).
- `ليس`: منطقي فقط.
- `في` / `ليس في`: عنصر في قائمة، أو نص جزئي في نص،
  أو مفتاح نصي في قاموس. غير ذلك خطأ نوع.
- شرط `إذا` و`بينما` و`كرر طالما` يجب أن يكون منطقيا،
  وليس عددا. الرقم 1 ليس صحيحا هنا.
- فهرسة القائمة: عدد صحيح داخل النطاق. فهرسة القاموس: نص
  موجود. فهرسة النص: عدد صحيح داخل النطاق.
- استدعاء الدالة: عدد المعاملات يجب أن يطابق التعريف.

التحويل الصريح (دوال مدمجة):
- `عدد(x)`: عدد كما هو، منطقي إلى 1/0، نص رقمي إلى عدد،
  غير ذلك خطأ نوع. النص غير الرقمي خطأ نوع.
- `نص(x)`: أي قيمة إلى نصها المطبوع. المنطقي إلى "صحيح"/"خطأ".
- `نوع(x)`: اسم النوع بالعربي: عدد، نص، منطقي، قائمة،
  قاموس، لاشيء، دالة.

دوال مدمجة أخرى: `طول`، `مدى`، `مجموع`، `أدنى`، `أقصى`،
`مطلق`، `اقرأ_ملف`، `اكتب_ملف`، `ادخل` (اختياري مع سؤال نصي).

## 4. Error Handling — رسائل الأخطاء

كل خطأ عربي، ويتضمن السطر والعمود ونوع الخطأ، بالصيغة:
`خطأ <النوع>: <الرسالة> (السطر X، العمود Y)`

أنواع الأخطاء:
- لغوي: حرف غير معروف، نص غير مغلق، مسافة بادئة غير متوقعة.
- نحوي: تعبير غير متوقع، توقع قوس أو نقطتين، كتلة فارغة،
  هدف تعيين غير صالح، فئة أو استيراد (غير مدعوم في v1).
- نوع: جمع نص وعدد، شرط غير منطقي، فهرس غير عدد،
  استدعاء قيمة ليست دالة، تحويل غير صالح.
- وقت التشغيل: متغير غير معرف، دالة غير معرفة، قسمة على صفر،
  فهرس أو مفتاح خارج النطاق، عدد معاملات غير صحيح،
  ارجع/اكسر/تابع خارج سياقه، تجاوز حد التكرار.
- إدخال/إخراج: تعذر قراءة أو كتابة ملف، وتعذر قراءة الإدخال.

أمثلة:
- `خطأ نوع: لا يمكن جمع نص وعدد (السطر 2، العمود 10)`
- `خطأ وقت التشغيل: متغير غير معرف: نتيجة (السطر 5، العمود 7)`
- `خطأ وقت التشغيل: قسمة على صفر (السطر 3، العمود 12)`

## 5. ما هو خارج v1

- الفئات (`فئة`) والاستيراد (`استورد`) والوصول بالنقطة
  (مثل `قاموس.values()`): المحلل يرفضها برسالة واضحة،
  لأنها تحتاج تصميم كائنات ووحدات في v2، وليست جزءا من
  النواة. الدوال المدمجة تغطي الحاجة في v1.
- لا Compiler إلى لغة آلة في v1، بقرار صريح من صاحب اللغة.
  الـ Interpreter كافٍ، والملف التنفيذي الناتج من Rust
  مستقل بذاته ولا يحتاج Python.

## 6. Phase 1A — الخطوة 1: المحلل الدلالي (منفذة 2026-11-05)

بعد اعتماد v1.3، بدأ تنفيذ Phase 1A بالخطوة 1:
محلل دلالي (`src/semantic.rs`) يعمل بعد التحليل
النحوي وقبل التنفيذ، ولا يغير دلالة اللغة.

ما يفحصه:
- قراءة متغير غير معرف في أي نطاق مرئي.
- `ارجع` خارج دالة، و`اكسر`/`تابع` خارج حلقة
  (حلقة خارج دالة لا تحسب لداخل دالة متداخلة).
- استدعاء دالة مستخدم معروفة أو دالة مدمجة
  بعدد معاملات خاطئ.
- معاملات مكررة في تعريف دالة، وهدف تعيين
  غير صالح (غير اسم أو اسم[فهرس]).

قواعد النطاق تطابق المفسر تماما: الدالة تفتح
نطاقا جديدا، والكتل لا تفتح نطاقا، ومتغير
الحلقة يبقى بعدها، واسم الدالة يضاف قبل
جسمها (للاستدعاء الذاتي)، والاستدعاء قبل
التعريف يفشل، كما في التنفيذ من أعلى لأسفل.

نوع خطأ جديد: `دلالي`، بصيغة:
`خطأ دلالي: متغير غير معرف: س (السطر X، العمود Y)`.
إذا فشل التحليل الدلالي، لا يعمل البرنامج
أبدا، فلا طباعة ولا كتابة ملف تحدث قبل الخطأ.

ما لا يفحصه بعد (خطوات 1A لاحقة، لا هذه):
الأنواع التدريجية، والوحدات/الاستيراد، والوصول
بالنقطة، والفئات/الواجهات. هذه ما زالت
مواصفة في v1.3، لا تنفيذ.
